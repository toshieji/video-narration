スライドを見ながら、1枚ずつ質問して台本を作る。既存の収録動画の文字起こしがあれば、その語り口・事例を土台にする。

引数: $ARGUMENTS
- 第1引数: スライドデッキ（`.pptx`）または画像化済みディレクトリ
- 第2引数以降（省略可）: 既存動画の文字起こしファイル（`scripts/extract_source_video.sh`の出力）

## 手順

### 1. 素材を読む
- `.pptx`が渡されたら `scripts/render_slides.sh` で画像化し、各スライドを実際に見る（Readツールで画像を読む）
- 文字起こしが渡されたら全文を読む。**どのスライドの話をしているか**を対応づける（スライドの文言と文字起こしの語彙が一致する箇所を探す）

### 2. スライドごとに質問する
**一度に全部聞かない。1枚ずつ進める。** スライドの中身は見えているので、「何が書いてあるか」は聞かない。聞くのは**書かれていないこと**だけ:

- このスライドで一番伝えたいことは何か
- 具体例・実体験を入れるか（あるなら概要）
- 前のスライドとどうつなぐか
- 触れてほしくないこと・避けたい表現はあるか

既存の文字起こしがある場合は、質問の前に**該当箇所を引用して見せる**:
> 前回はこのスライドで「（引用）」と話しています。この流れを踏襲しますか、それとも変えますか。

回答が箇条書き・断片でもよい。**文章化はこちらの仕事**。

### 3. 台本を書く
`skills/video-narration/SKILL.md` の形式で書き出す:

```
## スライドN（ラベル）
（話す内容の文章）
```

書くときのルール:
- **話し言葉**（読み上げられる前提。「〜である」でなく「〜です」）
- **1枚200〜600字**が目安（30〜100秒）
- **固有名詞・読みが割れる漢字はひらがなで書く**（例: 「対になる」→「たいになる」）。人間向けの資料では漢字のままにし、読み上げ用の台本だけひらがなにする
- 既存の文字起こしを使う場合、**そのまま貼らない**。話し言葉の重複・言い淀みを整理し、スライドの構成に合わせて再構成する

### 4. 確認を取る
書いた台本をスライドごとに提示し、**声にする前に**内容の確認を取る。音声を作り直すコストは低いが、台本の間違いは動画全体に残る。

### 5. 次の工程へ
台本が固まったら `/generate-narration-audio` へ進む。

## やらないこと
- **内容を勝手に創作しない。** スライドに書かれていないことを補うときは必ず確認する
- **既存の文字起こしを鵜呑みにしない。** 古い制度・廃止された仕組みの説明が含まれていることがある（実例: 過去動画に、現在は廃止された資格制度の説明が残っていた）。内容の鮮度は必ず確認する
